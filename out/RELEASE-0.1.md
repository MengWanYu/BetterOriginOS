# BetterOriginOS 0.1.0 测试版 · 发布稿

> 面向帖子/群公告的可直接粘贴版本。事实来源：`out/DEVLOG.md`、`vivo-OriginUI/docs/04-notification-row.md`、
> 真机验证日志 `work/os5-ref/notify-verify-20261026-*.log`。

## 一句话介绍

给 iQOO Z8（OriginOS 5）做的一组系统体验补丁：通知条改成 iOS 风格、通知中心媒体卡换样式，
外加两个烦人的系统 bug 修复。全部功能默认关闭，按需开启，随时可关回原生。

## 适配与依赖

| 项 | 说明 |
|---|---|
| 机型 / 系统 | iQOO Z8（V2314A / PD2314），OriginOS 5，Android 15 |
| 环境 | root（KernelSU）+ LSPosed |
| 模块作用域 | `com.android.systemui`、`com.android.providers.media.module`、`com.android.filemanager` |
| 设置端 | 自带 App（OriginOS 5 风格界面），功能开关 + 下拉选项 + 真实预览，改完一键重启 SystemUI |
| 包体 | 约 216 KB，无第三方依赖库 |

## 功能列表

### 1. 通知条 iOS 化（通知 · 默认关闭）

收起态原地重排，不动模板绑定链，点击/长按/滑动删除等原生交互全部保留。

- **38dp 应用图标**（自适应图标满幅化裁边）+ 标题/正文同列左对齐，去掉 app 名行与展开箭头
- **同 app 多条通知拆成独立卡片**，不再被系统合并成"应用类别卡"
- **卡片堆叠参数可选**：iOS（16dp 边距 / 8dp 间距 / 20dp 圆角）或 OS5 原生
- **【测试功能】OS6 折叠堆叠**（同 app 多条折叠成一叠）：正面是最新一条，卡下方逐层露边，图标右上角深色条数徽标；
  点卡片右上角箭头展开成组内列表（点卡体是打开 App），再点箭头收起。**可能不稳定，默认建议先用「完全分离」**
- **覆盖模板**：`base` / `big` / `bigText` / `inbox` / `bigPicture`；`messaging` / `conversation`
  用同规格的覆盖行（保留原模板的数据绑定，聊天内容不丢）
- **媒体通知豁免**：MediaStyle 通知交给下面的媒体卡功能，避免两个功能互相打架
- 日间 / 夜间 / 字体缩放 1.3 三种配置真机实测通过；RTL 未测（本机无法给 SystemUI 切 ar 语言）

### 2. 通知中心媒体卡（通知 · 默认关闭）

- 两种样式：**OS5 原子随身听** / **Material You**，下拉菜单带预览图
- 进度条可拖动 seek，按钮区随样式重排
- 针对 vivo MediaStyle 通知实现，标准 MediaSession 走通用分支

### 3. 媒体选择器相册修复（媒体 · 默认关闭）

- 照片选择器显示全部自建相册（修复系统只显示默认相册、其它相册"消失"的问题）

### 4. 文件管理重命名修复（文件 · 默认关闭）

- 重命名长度上限 **56 → 85 字符**，长下载文件名不再被掐断

## 已知限制（0.1 阶段）

- **heads-up 横幅**仍是 vivo 自绘胶囊，本版不改
- **展开态保持原生**（iOS 化只做收起态）
- **自定义视图通知**（App 自带 RemoteViews 布局）不改
- 卡片背景材质/模糊沿用系统，非自绘
- **OS6 折叠堆叠是测试功能**：heads-up 横幅与堆叠卡的联动、RTL 尚未实测，**可能不稳定**；
  遇到异常把「分组方式」切回「完全分离」或关掉「通知」功能再重启 SystemUI 即可

## 安装步骤

1. LSPosed 中安装并启用 `BetterOriginOS.apk`
2. 勾选作用域：`SystemUI`、`MediaProvider`、`文件管理`（三个都要）
3. 打开 BetterOriginOS App，进入对应功能卡片，打开开关并选样式
4. 按 App 内提示重启 SystemUI（或手动 `adb shell "su -c 'killall com.android.systemui'"`）
5. 出现异常时：把对应功能关掉再重启 SystemUI 即可回退

## 质量口径（为什么可以直接用）

- 通知条改造配了**代码级校验器**（`work/verify_notify.py`）：直接读视图 bounds、字号、颜色、
  端距做断言，不靠肉眼看截图。本轮 10 条普通行 + 3 条堆叠行（折叠、展开两种形态各测一次）全部 PASS；
  校验器还会反查屏上证据，"没测到"直接算 FAIL 而不是通过
- 日夜切换、字体缩放 1.3 两套配置分别复跑，均通过；RTL 未实测
- 崩溃回归：`logcat -b crash` 0 条 FATAL（此前两个真实崩溃——配置变化后参数回退、
  行复用残留旧覆盖行——已修复并复现验证）

## 更新要点（相对内部版本）

- 新增：通知条 iOS 化（含拆分为独立卡片、卡片堆叠参数、messaging 覆盖行、模板补测）
- 修复：系统字体/密度等配置变化后通知条参数回退成原生
- 修复：通知行被系统回收复用时残留上一条通知的覆盖行
- 修复：滑动删除等手势在改造后的行上失效
- 新增：OS6 折叠堆叠样式（露边 + 条数徽标 + 箭头展开组内列表），行高由卡片自量单一真源驱动
- 新增：180ms 展开/收起过渡动画，逐帧与行高同源
- 移除：通知列表底部的 AOSP NotificationShelf（装不下的通知被压成一条图标收纳栏），
  改为继续向下排列 + 滚动，与 OS6 行为一致
